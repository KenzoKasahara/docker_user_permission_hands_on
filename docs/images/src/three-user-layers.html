Dockerで登場する「3種類のユーザー」

同じ「ユーザー」でも、層が違えば目的も管理場所も別物

ユーザーの種類 / 管理場所
具体例
役割
1
アプリケーションユーザー
Django（User / Group / Permission）
データベースに保存される
管理者 編集者 閲覧者
ブラウザからログインする人
画面やAPIを利用する
誰であるか・何をしてよいかは
Djangoが判定する
Djangoが許可した処理を、コンテナ内のプロセスが実行する
2
コンテナ内のLinuxユーザー
Dockerfile（USER appuser）
コンテナイメージに含まれる
appuser postgres nginx
コンテナごとの実行ユーザー（非root）
コンテナ内でプロセスを実行する
コンテナ内のファイルへの
読み書き権限を持つ
コンテナは、ホストOS上のDockerによって動かされる
3
ホストOSのユーザー
サーバーのLinux（SSH・dockerグループ）
CI/CDの実行ユーザーも含む
サーバー管理者 デプロイ担当者
権限を与える相手は最小限にする
Dockerを起動・停止・更新する
実質的にroot相当の
強い権限になる
3層は独立している

Djangoの管理者ユーザーを作っても、その人がサーバーへSSH接続できるようになるわけではない。
反対に、SSH接続できる人が、自動的にDjangoの管理画面を利用できるわけでもない。
