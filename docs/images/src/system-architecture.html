全体構成 ─ コンテナごとの役割と実行ユーザー

1つのDjangoアプリを、役割ごとに分けたコンテナで動かす。利用者ごとにコンテナを分ける必要はない

利用者のブラウザ
管理者・編集者・閲覧者は、すべて同じ入口からアクセスする
アクセスする人
アプリ利用者
HTTPS インターネット経由で、公開しているポートへ届く
ホストOS（Dockerを動かすサーバー） ― この中はDockerネットワークでつながっている
Nginxコンテナ（リバースプロキシ）
外部からの通信を受け付け、HTTPSの処理を担当する
実行ユーザー
nginx
HTTP アプリの処理をDjangoへ渡す
Djangoコンテナ（アプリケーション）
アプリの処理を行う。一般利用者・管理者などの判定もここで行う
実行ユーザー
appuser（非root）
SQL DB接続用のユーザー（appdb_user）でPostgreSQLへ接続する
PostgreSQLコンテナ
データを保存する。インターネットへ直接公開しない
実行ユーザー
postgres
コンテナを作り直してもデータが消えないよう、外へ書き出す
データ保存領域（ボリューム）
実体はホストOS側にある。UID/GIDの不一致による権限エラーが起きやすい場所
書き込む人
postgres
外から入れる入口は1つだけにする

外部へ公開するのはNginxのポートだけで、DjangoとPostgreSQLはホストOSの内側に閉じておく。
コンテナはそれぞれ別の実行ユーザーで動かし、1つ乗っ取られても影響範囲が広がらないようにする。
